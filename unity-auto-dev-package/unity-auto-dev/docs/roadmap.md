# Roadmap

Статусы: `[ ]` — ожидает выполнения, `[x]` — выполнено, `[!]` — заблокировано/нужно решение пользователя.
Одна задача = одна сессия OpenCode. Не брать следующую задачу в рамках той же сессии.

## Этап A. Первое существо: базовая архитектура и навигация

- [ ] **DINO-001** Изучить текущую структуру AI/Data и определить минимальный контракт CreatureController. Не менять код; зафиксировать найденные зависимости и план файлов в progress.md.
- [ ] **DINO-002** Создать `CreatureConfig` ScriptableObject-класс с начальными параметрами навигации, восприятия, памяти и атаки. Не создавать/редактировать `.asset`.
- [ ] **DINO-003** Создать `CreatureNavigator` на базе NavMeshAgent: кэширование компонента, установка/сброс цели, остановка, скорость, проверка доступности пути и безопасные проверки состояния агента.
- [ ] **DINO-004** Создать `CreatureController` как точку композиции: ссылки на config, NavMeshAgent и компоненты существа; минимальная валидация ссылок и понятные сообщения об ошибках.
- [ ] **DINO-005** Добавить минимальное состояние Idle и `CreatureStateMachine` (если это оправдано найденной архитектурой). Не переносить FSM игрока механически; не создавать универсальный фреймворк.
- [ ] **DINO-006** Добавить возможность задать исходную точку существа и команду вернуться к ней. Пока без патруля и восприятия.
- [ ] **DINO-007** Добавить простую настройку Animator-параметров движения существа, только если известны фактические имена параметров/анимаций. Иначе создать ручную задачу и не выдумывать их.

## Этап B. Зрение и память о цели

- [ ] **DINO-008** Реализовать `CreatureTargetMemory`: текущая цель, последняя известная позиция, время последнего обнаружения, сброс памяти. Не принимать решения о переходах состояний.
- [ ] **DINO-009** Реализовать проверку зрения: дистанция, угол обзора, raycast видимости и LayerMask препятствий. Использовать только игрока как цель первой версии.
- [ ] **DINO-010** Добавить периодический тик восприятия с настраиваемым интервалом; не выполнять полный набор Physics-проверок каждый кадр.
- [ ] **DINO-011** Подключить обнаружение игрока к памяти цели и переключению Idle/Investigate/Chase. Если текущая FSM ещё не готова, сначала создать только выдачу результата perception без обходного дублирования логики.
- [ ] **DINO-012** Реализовать `Chase`: обновлять destination с ограниченной частотой, прекращать погоню при потере цели согласно таймеру памяти, не дёргать destination каждый кадр без необходимости.
- [ ] **DINO-013** Реализовать `Investigate`: двигаться к позиции, где игрок был замечен/услышан; завершать состояние по достижении точки или истечении таймера.
- [ ] **DINO-014** Реализовать `Search`: ограниченный по времени поиск вокруг последней известной позиции. Не реализовывать сложную тактику обхода укрытий.
- [ ] **DINO-015** Реализовать `Return`: после неудачного поиска вернуться к исходной точке и перейти в Idle.

## Этап C. Слух

- [ ] **DINO-016** Спроектировать простой контракт шума: позиция, сила и источник/идентификатор при необходимости. Сначала проверить, нет ли уже подходящей системы событий.
- [ ] **DINO-017** Реализовать приём шума существом и расчёт эффективной дальности по силе шума и параметрам слуха.
- [ ] **DINO-018** Подключить шум к Investigate: шум сообщает приблизительную позицию, но сам по себе не делает игрока постоянно видимой целью.
- [ ] **DINO-019** Добавить отправку событий шума от игрока для выбранных действий (например, бег и приземление). Не менять PlayerController широко; использовать минимальную точку интеграции.
- [ ] **DINO-020** Согласовать и реализовать правила приоритета зрительного обнаружения и слухового события, включая поведение при уже активном Chase.

## Этап D. Ближняя атака

- [ ] **DINO-021** Изучить наличие системы здоровья/получения урона у игрока. Если её нет, описать минимальный контракт и вынести согласование в manual-queue.md.
- [ ] **DINO-022** Реализовать компонент `CreatureAttack`: дистанция, сектор атаки, cooldown и защита от повторного нанесения урона в одном замахе.
- [ ] **DINO-023** Реализовать состояние Attack: остановка/контроль дистанции, начало атаки только при выполнении условий, возврат к Chase если цель вышла из зоны.
- [ ] **DINO-024** Подключить нанесение урона через согласованный контракт. Не создавать вторую систему здоровья и не вызывать урон каждый кадр.
- [ ] **DINO-025** Добавить анимационный trigger/событие атаки только после подтверждения имён параметров и доступности нужной анимации. Если нужен ручной Animation Event, записать его в manual-queue.md.

## Этап E. Сборка существа в Unity и доводка первой версии

- [ ] **DINO-026** Подготовить список обязательных компонентов и ссылок на префаб существа; кодом префаб не редактировать.
- [ ] **DINO-027** Проверить кодовые граничные случаи статическим чтением изменённых файлов: отсутствующие ссылки, невалидный NavMeshAgent, отсутствие пути, уничтоженная цель. Не запускать сборку/тесты.
- [ ] **DINO-028** Составить короткую ручную процедуру настройки NavMesh, слоёв, коллайдеров, Animator и префаба в Unity Editor.
- [ ] **DINO-029** После ручной настройки пользователя обработать его замечания и исправить только подтверждённые проблемы.
- [ ] **DINO-030** Зафиксировать критерии готовности первой версии существа и итоговое состояние в progress.md.

## Следующие крупные этапы (пока без детальной декомпозиции)

### Интерфейс персонажа
- HUD и отображение основных параметров игрока.
- Связь UI с существующими событиями/данными игрока.
- Настройка Canvas, префабов и визуальных ассетов вручную в Unity.

### Карта
- Основа карты и отображение текущего положения игрока.
- Ресурсы и маркеры ресурсов.
- Ландшафт и ориентиры.
- Точки интереса.
- Масштабирование, перемещение и фильтры карты.

Эти этапы не должны автоматически выполняться раньше задач существа без изменения приоритета пользователем.
