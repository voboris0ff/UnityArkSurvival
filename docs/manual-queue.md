# Очередь ручных действий

Здесь находятся только действия, которые пользователь должен выполнить в Unity Editor или решения, которые нельзя безопасно принять за него.

## Ожидает выполнения

### [x] DINO-001 — зафиксировать слои для восприятия существа (подготовка к DINO-009/DINO-010)
- **Что сделать:** в Unity Editor в `Edit → Project Settings → Tags and Layers` проверить/создать слои для:
  - препятствий, которые перекрывают зрение существа (по умолчанию можно взять существующие `Default`/`Environment`, если они есть);
  - игрока — в сцене объект `Player` уже находится на layer 6, убедитесь, что слой называется осмысленно (например `Player`);
  - самого существа (например `Creature`) — после создания префаба.
- **Зачем:** DINO-009 (raycast зрения) и DINO-010 требуют отдельный LayerMask препятствий и однозначного слоя цели; без них нельзя корректно настроить проверку видимости.
- **Готово, когда:** слои существуют, названия известны, и вы указали их агенту (нужны имена, а не только номера).
- **Блокирует:** DINO-009, DINO-010 (создание кода DINO-002..DINO-008 не блокируется).

### [x] DINO-001 — запечь NavMesh на тестовой сцене (подготовка к DINO-003/DINO-026)
- **Что сделать:** в `SampleScene` добавить `NavMeshSurface` (на объект навигационного окружения), настроить `Agent`/`Include Layers`, запечь NavMesh (`Bake`). В сцене сейчас `m_NavMeshData: {fileID: 0}` — навигации нет.
- **Зачем:** `CreatureNavigator` на `NavMeshAgent` не сможет работать без запечённой поверхности; проверка `isOnNavMesh` и доступность пути в коде будут всегда ложно-отрицательными.
- **Готово, когда:** NavMesh виден в Scene-view (синяя сетка).
- **Блокирует:** проверку навигации в DINO-003+ (код писать можно).

### [x] DINO-001 — подтвердить анимации существа (подготовка к DINO-007/DINO-025)
- **Что сделать:** сообщить агенту, есть ли Animator Controller существа и какие в нём точные имена параметров/триггеров и анимации (idle/walk/run/attack).
- **Зачем:** DINO-007 и DINO-025 запрещают выдумывать имена параметров Animator.
- **Готово, когда:** список имён параметров/анимаций передан агенту.
- **Блокирует:** DINO-007, DINO-025.

### [ ] DINO-004 — назначить параметры NavMeshAgent существа (подготовка к DINO-003/DINO-004)
- **Что сделать:** после создания префаба существа добавить на него компонент `NavMeshAgent` и настроить: `Agent Type` (создать отдельный тип для существа, если размер отличается от человека), `Radius`, `Height`, `Base Offset`, `Speed`, `Angular Speed`, `Acceleration`, `Stopping Distance`, `Area Mask`. Убедиться, что `NavMeshSurface` запекает поверхность под этот `Agent Type`.
- **Зачем:** `CreatureNavigator` (DINO-003) в `Initialize` перезаписывает `speed` и `stoppingDistance` из `CreatureConfig` по горизонтальной логике; `Agent Type` и `Area Mask` берутся из агента и напрямую влияют на `NavMesh.SamplePosition` и доступность пути (`PathPartial`).
- **Готово, когда:** агент стоит на запечённом NavMesh (`isOnNavMesh = true`), существо проезжает по сцене без провалов и частичных путей там, где путь очевидно есть.
- **Блокирует:** проверку навигации в DINO-004+.

### [ ] DINO-021 — согласовать контракт урона у игрока (предварительное решение)
- **Что сделать:** решить, как существо наносит урон игроку. В `Assets/Scripts` системы здоровья нет (`Health`/`Damage`/`Attack` не найдены).
- **Зачем:** по `project-context.md` нельзя создавать вторую систему здоровья; нужен явный контракт (`IDamageable`, метод на игроке и т.п.).
- **Готово, когда:** выбранный вариант зафиксирован.
- **Блокирует:** DINO-022, DINO-024.

## Правила ведения очереди
- Не добавлять сюда действия, которые агент может выполнить обычным изменением C# или Markdown.
- Каждый пункт должен содержать: что сделать, где сделать, зачем и как понять, что готово.
- После выполнения пользователь отмечает пункт `[x]` или сообщает агенту, что он выполнен.
- Если ручное действие блокирует дальнейшую разработку, явно указать блокирующие задачи.
- Не удалять выполненные пункты: переносить их в раздел «Выполнено» для сохранения истории.
