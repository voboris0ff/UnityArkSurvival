# Очередь ручных действий

### DINO-030 — обязательные компоненты и ссылки префаба существа
- **Что сделать:** сверить префаб существа со списком ниже и ответить, чего не хватает или что сделано иначе.
  1. Корень префаба: `NavMeshAgent` и `CreatureController`. У `CreatureController` обязателен только `Config` (объект `CreatureConfig`); `Agent`, `Home Point`, `Eye Point`, `Target` можно оставить пустыми — агент и цель найдутся сами, дом — стартовая позиция, глаза — корень + `EyeHeight`.
  2. Модель с `Animator`: параметр `Speed` (float), триггер `Attack`, состояния `idle` / `walk` / `run`; `Apply Root Motion` выключится сам.
  3. На объекте с `Animator`: `CreatureAttackAnimationEvent`; в клипе атаки — событие `OnAttackHit` без аргументов в кадре удара.
  4. На корне: `CreatureAnimator` (ссылки подставятся сами) — без него нет анимации движения и атаки.
  5. Игрок: слой `Player` и нетриггерный `Collider`.
  6. `CreatureConfig.ObstacleLayerMask`: слой `Obstacle`; по умолчанию в маске стоит `Default`, то есть ничего не перекрывает.
  7. Префаб стоит на запечённом NavMesh, иначе поведение не запустится.
  8. Для ручных проверок: объект с `CreatureDebugInput` (`R` — возврат) и `CreatureNoiseDebugInput` (`N` — шум).
- **Где:** `Assets/` — префаб существа, `CreatureConfig` в `Assets/Scripts/Data/`, `Raptor.controller`.
- **Зачем:** без этих компонентов и ссылок существо молчит или не двигается; список — точка отсчёта для DINO-032.
- **Готово, когда:** префаб содержит все пункты 1–4, и в ответе перечислено, что отличается.
- **Ответ пользователя:**
  Всё выполненно
